🐳 ClusterMate diagnosis report

Summary (one paragraph, what is broken)

The pod broken-web-6947985cb4-v9tb5 in the clustermate-demo namespace is stuck in a Pending state because Kubernetes cannot pull the container image. The application is trying to run an image named nginx:9.9.9-nonexistent, which does not exist on the Docker registry, causing the pod to fail repeatedly with an ImagePullBackOff error.

Root cause (the single most likely cause)

The root cause is that the image tag specified in the Deployment configuration (nginx:9.9.9-nonexistent) is incorrect or fictional; this specific image does not exist on the registry, so Kubernetes cannot download it to run the container.

Evidence (bullet list mapping each claim to snapshot data)

  • Pod State: The pod broken-web-6947985cb4-v9tb5 has a phase of Pending, meaning it is waiting for resources but not running yet.
  • Container State: Inside the container named web, the state is ImagePullBackOff, indicating Kubernetes tried to fetch the image but failed.
  • Specific Error: The event logs explicitly state: Failed to pull image "nginx:9.9.9-nonexistent": ... docker.io/library/nginx:9.9.9-nonexistent: not found.
  • Retry Behavior: The pod has been in a "Back-off" loop (14 attempts), trying to pull the same non-existent image over time.
  • Missing Image: There is no evidence of a CreateContainerConfigError (missing config map) or OOMKilled (memory issues); the failure is strictly about the image not being found.

    • Suggested fix (numbered kubectl commands, copy-paste ready)

  • Verify the image tag: Check if the tag 9.9.9-nonexistent actually exists on your registry. Run:

    • docker pull nginx:9.9.9-nonexistent

    # If this fails with "manifest unknown" or similar, the tag is wrong.

  • Fix the Deployment: Once you know the correct tag (e.g., nginx:latest or a specific version like 1.25-alpine), update your deployment to use it. Replace <correct-tag> with your actual valid tag:

    • kubectl set image deployment/broken-web web=nginx:<correct-tag> -n clustermate-demo

  • Verify the fix: Watch the pod status to ensure it moves from Pending to Running:

    • kubectl get pods -n clustermate-demo -w
